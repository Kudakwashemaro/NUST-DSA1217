Section 01 · Foundation
Introduction & Abstract Data Types
The vocabulary of data structures. Learn what ADTs are and why they matter before touching any real structure.
⬇ Low exam weight — cover quickly

What is a Data Structure?

A data structure is a way of organizing and storing data in memory so that it can be accessed and modified efficiently. Think of it like choosing between a pile of books vs. an organised shelf — same books, very different access times.

A data structure has two components: a set of operations that can be performed on data (its interface) and the way data is organized in memory (its implementation). Good data structure choice is critical — using the wrong one can make a fast algorithm slow.

An algorithm is a finite, well-defined sequence of steps that solves a problem. It must: take input, produce output, be definite (no ambiguity), be finite (it stops), and be effective (each step is executable).

Algorithm vs Program

An algorithm is the idea/logic — language independent. A program is the actual implementation in code. You can have one algorithm expressed in Python, Java, C++, etc. The algorithm for binary search is the same whether coded in Python, Java, or C — the program differs, the algorithm does not.

Primitive vs Abstract Data Types

Type What it is Examples
Primitive Built-in, directly operated on by hardware int, float, char, bool
Abstract (ADT) Conceptual model — defined by behaviour, not structure Stack, Queue, List, Tree, Graph
Composite Built from primitives or other types Array, Struct, Record

Abstract Data Types (ADTs)

An ADT is a mathematical model of a data structure that specifies: (1) the data it stores, and (2) the operations it supports — but not how those operations are implemented. It's the "what", not the "how". ADTs act as a contract between the user of a data structure and its implementor.

Analogy: A car's steering wheel is an ADT — you know turning it left makes the car go left (the interface), but you don't need to know the mechanics of the steering column (the implementation). Similarly, a TV remote is an ADT — you press "Volume Up" without knowing the IR signal encoding.

User code depends only on the ADT interface — the implementation can change freely

Benefits of ADTs

  • Encapsulation: Implementation details are hidden from the user
  • Modularity: You can swap implementations without changing code that uses the ADT
  • Reusability: Same ADT can be used in different programs
  • Abstraction: Focus on what operations do, not how
  • Maintainability: Easier to update and debug since changes stay within the implementation layer

Python — Stack ADT concept
# An ADT defines WHAT operations exist, not HOW they work
# Stack ADT interface:
#   push(item)  → add item to top
#   pop()       → remove and return top item
#   peek()      → return top item without removing
#   is_empty()  → return True if stack is empty
#   size()      → return number of items

class StackADT:
    def push(self, item): pass  # Must be implemented
    def pop(self): pass
    def peek(self): pass
    def is_empty(self): pass
    def size(self): pass

# The SAME interface can have two totally different implementations:
# Implementation A: uses a list (array-backed)
class ArrayStack(StackADT):
    def __init__(self): self._data = []
    def push(self, item): self._data.append(item)
    def pop(self): return self._data.pop()
    def peek(self): return self._data[-1]
    def is_empty(self): return len(self._data) == 0
    def size(self): return len(self._data)

# User code works identically with EITHER implementation!
s = ArrayStack()
s.push(10)
s.push(20)
print(s.pop())  # → 20

Characteristics of a Good Algorithm

  • Input: Zero or more well-defined inputs
  • Output: At least one well-defined output
  • Definiteness: Each step must be unambiguous — no room for interpretation
  • Finiteness: Must terminate after a finite number of steps (infinite loops ≠ algorithm)
  • Effectiveness: Every step must be feasible and basic enough to be done by a person with pen and paper
  • Efficiency: Should use minimal time and space resources (not always listed as a formal property, but critical in practice)
EXAM TIP: Know the 5 characteristics by heart. "Effectiveness" is often confused with "Efficiency" — they are different. Effectiveness = steps are executable; Efficiency = uses resources wisely. An algorithm can be effective (each step is doable) but inefficient (takes O(n!) steps).

Why ADTs Matter in Software Engineering

The concept of an ADT was formally described by Barbara Liskov and Stephen Zilles in 1974. It is the foundation of object-oriented programming: when you define a class in Python or Java, you are essentially creating an ADT — the class's public methods form the interface, and the class body is the implementation.

The key insight is information hiding: by exposing only the necessary operations and hiding the internal details, you reduce the complexity that any one programmer must understand. This makes programs easier to maintain, test, and scale.

The List ADT — The Most General Structure

The List ADT is the most fundamental. It maintains an ordered sequence of elements and supports: get(i) — retrieve element at position i; insert(i, x) — add element x at position i; remove(i) — delete element at position i; size() — return number of elements. The Stack and Queue ADTs are restricted forms of the List ADT — they limit which positions insertions and deletions can happen at.

Data Structure vs Algorithm — The Relationship

Data structures and algorithms work together. A data structure by itself does nothing — it just stores data. An algorithm by itself is just logic — it needs data to work on. The choice of data structure directly affects the efficiency of an algorithm. Example: Binary search runs in O(log n) on a sorted array, but O(n) on a sorted linked list because linked lists have no random access.

Why Analyze Algorithms?

Two algorithms can solve the same problem but take vastly different amounts of time or memory. Algorithm analysis gives us a language-independent, hardware-independent way to compare them. Without analysis, you might choose a slow algorithm that works fine for 10 items but takes hours for 10,000.

We measure two things: Time Complexity (how many steps does it take?) and Space Complexity (how much memory does it use?). Both are measured as a function of the input size n. We care about how performance scales as n grows, not the exact number of steps on any single machine.

Formal Definition of Big-O: We say f(n) = O(g(n)) if there exist positive constants c and n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀. In plain English: Big-O describes the growth rate — how much slower the algorithm gets as input doubles, independently of hardware speed.

The Three Cases

Best Case (Ω — Omega)

  • The most favourable input possible
  • Example: searching for the first element
  • Gives a lower bound on time
  • Omega notation: Ω(f(n))

Average Case (Θ — Theta)

  • Expected time over all possible inputs
  • Most realistic for real-world analysis
  • Theta notation: Θ(f(n))
  • Hardest to compute mathematically

Worst Case (O — Big-O) ← This is what matters for exams

  • The most unfavourable input possible — maximum time the algorithm can take
  • Big-O gives an upper bound — the algorithm will NEVER be slower than this
  • This is what your lecturer expects you to know
  • Example: linear search worst case = element is last or not found = O(n)
EXAM FACT: Big-O notation expresses upper bounds (worst case). Big-Omega expresses lower bounds (best case). Big-Theta expresses tight bounds (average case). Your lecturer confirmed: Big-O = Upper bounds.

How to Calculate Big-O

Rules for simplifying Big-O: (1) Drop constants: O(2n) = O(n). (2) Drop lower-order terms: O(n² + n) = O(n²). (3) Loops multiply: a loop inside a loop = O(n²). (4) Sequential code adds: O(n) + O(n²) = O(n²).

Python — Identifying Big-O
# O(1) — Constant: no loop, direct access
def get_first(arr):
    return arr[0]  # Always 1 step regardless of array size

# O(n) — Linear: one loop through n elements
def linear_search(arr, target):
    for item in arr:       # n iterations
        if item == target:
            return True
    return False

# O(n²) — Quadratic: nested loops
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):        # outer loop: n
        for j in range(n-1):  # inner loop: n → total n²
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]

# O(log n) — Logarithmic: halving input each step
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: low = mid + 1
        else: high = mid - 1
    return -1
KEY FACT from test: Replacing a value at A[k] (array index access) is O(1) — because arrays have direct access. All queue operations are O(1). Linear search worst case = O(n).

Arrays
The simplest and most fundamental data structure. The backbone of most other structures.

What is an Array?

An array is a contiguous block of memory storing elements of the same type, accessed via a numerical index. The first element is at index 0. Direct access to any element by index is O(1) — this is the array's superpower.

EXAM: Arrays allow direct (random) access to any element. This is what makes them unique vs linked lists.

Static Arrays

  • Fixed size set at creation
  • Size cannot change
  • Memory allocated once (stack)
  • Example: arr = [0] * 10

Dynamic Arrays

  • Size grows/shrinks as needed
  • Python lists ARE dynamic arrays
  • Resizing copies all elements O(n)
  • Amortized O(1) append

Array Operations & Complexities

Operation Best Average Worst Notes
Access A[k] O(1) O(1) O(1) Direct index calculation
Search (unsorted) O(1) O(n) O(n) May need to check every element
Insert at end O(1) O(1) O(n) Worst: array is full, needs resize
Insert at position i O(1) O(n) O(n) Must shift elements right
Delete at position i O(1) O(n) O(n) Must shift elements left
Python — Array Operations
# Python lists are dynamic arrays
arr = [10, 20, 30, 40, 50]

# O(1) - Direct access by index
print(arr[2])       # → 30
arr[2] = 99         # Replace: O(1) ← exam question!

# O(n) - Insert at beginning (shifts everything)
arr.insert(0, 5)   # [5, 10, 20, 99, 40, 50]

# O(1) amortized - Append to end
arr.append(60)     # Add to end

# O(n) - Delete (shifts elements)
arr.pop(0)         # Remove first element
arr.remove(99)     # Remove by value

# Traverse: O(n)
for i, val in enumerate(arr):
    print(f"arr[{i}] = {val}")

# 2D Array (Multidimensional)
matrix = [[1,2,3],[4,5,6],[7,8,9]]
print(matrix[1][2])  # → 6 (row 1, col 2)

Array Memory Layout — How It Works

Every array element occupies equal-sized consecutive memory slots. If the array starts at address 1000 and each int is 4 bytes, then: arr[0] = address 1000, arr[1] = 1004, arr[2] = 1008, arr[k] = 1000 + k×4. This is why access is O(1) — the CPU can compute the address instantly from the index with a single multiplication.

2D Arrays — Row-Major vs Column-Major Order

In a 2D array with r rows and c columns, elements are stored linearly in memory. Python stores rows consecutively (row-major order), which is the standard in C. Column-major (used in Fortran, MATLAB) stores columns consecutively. This matters for performance: iterating row-by-row is faster in Python because it's cache-friendly.

Why Python Lists Are NOT Arrays (Technically)

Python's list is actually a dynamic array of pointers (object references), not a contiguous block of same-typed values. Each element can be a different type because Python stores a reference (pointer) to each object, not the object itself. For true arrays in Python, use array.array or numpy.ndarray. However, for exam purposes, treat Python lists as arrays.

Cache Locality — Why Arrays Beat Linked Lists in Practice

Modern CPUs load memory in cache lines (typically 64 bytes). When you access arr[0], the CPU automatically loads arr[0] through arr[15] (for 4-byte ints) into cache. So accessing arr[1] next is almost free — it's already in the cache. Linked list nodes are scattered in memory, so each traversal step often causes a cache miss, requiring a slow memory fetch. This is why array traversal is much faster in practice than the O(n) complexity alone suggests.

Advantages and Disadvantages of Arrays

Advantages: Random access O(1); cache-friendly; simple index arithmetic; good for mathematical operations. Disadvantages: Fixed size (static arrays); insertion/deletion at arbitrary positions requires shifting O(n); memory must be allocated as one contiguous block (may fail for very large arrays on fragmented heaps).

Linked Lists
Dynamic memory allocation through nodes and pointers. Three variants: singly, doubly, circular.

What is a Linked List?

A linked list is a sequence of nodes, where each node contains: (1) the data, and (2) a pointer to the next node. Unlike arrays, elements are not contiguous in memory — they're scattered and linked by pointers.

EXAM: A node in its most basic form = one area for data + one area for a pointer to the next node. This was a direct question in your test.
Node structure: ┌──────────┬──────────┐ │ DATA │ NEXT ──┼──→ next node └──────────┴──────────┘ Singly Linked List: [10|●]──→[20|●]──→[30|●]──→[40|NULL] head tail

Singly Linked List — Full Implementation

Python — Singly Linked List
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None  # Pointer to next node

class LinkedList:
    def __init__(self):
        self.head = None

    def insert_at_front(self, data):  # O(1)
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    def insert_at_end(self, data):   # O(n)
        new_node = Node(data)
        if not self.head:
            self.head = new_node
            return
        current = self.head
        while current.next:          # Walk to the end
            current = current.next
        current.next = new_node

    def delete(self, data):          # O(n)
        if not self.head: return
        if self.head.data == data:
            self.head = self.head.next
            return
        current = self.head
        while current.next:
            if current.next.data == data:
                current.next = current.next.next  # Skip node
                return
            current = current.next

    def search(self, data):           # O(n)
        current = self.head
        while current:
            if current.data == data: return True
            current = current.next
        return False

    def reverse(self):               # O(n)
        prev = None
        current = self.head
        while current:
            next_node = current.next  # Save next
            current.next = prev       # Reverse pointer
            prev = current            # Move prev forward
            current = next_node       # Move current forward
        self.head = prev

    def display(self):
        current = self.head
        while current:
            print(current.data, end=" → ")
            current = current.next
        print("NULL")

Doubly Linked List

Each node has two pointers: next (forward) and prev (backward). This allows traversal in both directions but uses more memory.

NULL ←─[10|prev|next]─↔─[20|prev|next]─↔─[30|prev|next]─→ NULL head tail

class DNode:

        self.next = None  # Forward pointer

Circular Linked List

The tail node's next pointer points BACK to the head — forming a circle. There is no NULL at the end. This was a direct exam question: "How is a circular linked list created?" → By pointing to the head node from the tail node's 'next' pointer.

Stacks
LIFO structure. Used for recursion, expression evaluation, palindrome testing, undo operations.

Stack — LIFO (Last In, First Out)

A stack is like a pile of plates — you can only add or remove from the top. The last item added is the first one removed. This is LIFO.

EXAM FACTS: Stack = LIFO. Stack is used for: recursion (call stack), palindrome testing, expression evaluation, undo/redo, bracket matching.
PUSH → [ TOP → 40 ] ← POP [ 30 ] [ 20 ] [ BOTTOM → 10 ]
Python — Stack Implementation
class Stack:
    def __init__(self):
        self.items = []   # Using list as underlying array

    def push(self, item):   # O(1)
        self.items.append(item)

    def pop(self):           # O(1)
        if self.is_empty():
            raise IndexError("Stack is empty")
        return self.items.pop()

    def peek(self):          # O(1) - look without removing
        if self.is_empty():
            return None
        return self.items[-1]

    def is_empty(self):     # O(1)
        return len(self.items) == 0

    def size(self):          # O(1)
        return len(self.items)

# Application: Palindrome Check
def is_palindrome(word):
    s = Stack()
    for char in word:
        s.push(char)        # Push all chars
    reversed_word = ""
    while not s.is_empty():
        reversed_word += s.pop()  # Pop reverses order
    return word == reversed_word

print(is_palindrome("racecar"))  # True
print(is_palindrome("hello"))    # False

Stack — Real-World Applications

The stack's LIFO behaviour makes it the natural fit for any process that needs to undo or backtrack:

  • Function Call Stack: When function A calls B which calls C, each call is "pushed" onto the call stack. When C returns, it's "popped" and execution resumes in B. This is why stack overflow happens with infinite recursion.
  • Browser History: Each visited page is pushed. The back button pops to the previous page.
  • Undo/Redo: Text editors push each action onto an undo stack. Ctrl+Z pops the last action.
  • Expression Evaluation: Compilers use stacks to evaluate expressions and check bracket matching.
  • DFS Graph Traversal: Depth-first search uses a stack (or recursion = implicit stack).

Stack grows upward. Push adds to top; Pop removes from top. LIFO order.

Bracket Matching — Classic Stack Application

Python — Bracket/Parenthesis Matching
def is_balanced(expr):
    # Match (), [], {} using a stack
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for ch in expr:
        if ch in '([{':
            stack.append(ch)          # Opening — push
        elif ch in ')]}':
            if not stack or stack[-1] != pairs[ch]:
                return False  # Mismatch!
            stack.pop()               # Closing matches — pop
    return len(stack) == 0  # True if all opened were closed

print(is_balanced("({[]})"))    # True
print(is_balanced("({[})"))     # False — ] closed before [
print(is_balanced("((("))       # False — 3 unclosed

The Function Call Stack — Most Important Stack

Every program has a hidden stack called the call stack. When a function is called, a stack frame is pushed onto it, containing: local variables, parameters, and the return address (where to go after the function finishes). When the function returns, the frame is popped. This is why recursive functions push many frames — and why deep recursion causes a "stack overflow" error when the stack runs out of memory.

Why Stacks are Implemented with Lists (Not Linked Lists) in Python

Python's list.append() and list.pop() are both O(1) amortized, making lists the ideal stack implementation. A linked list would also work (O(1) for insert/delete at head), but has higher memory overhead per node and worse cache locality. For the exam: know that both array-backed and linked-list-backed stacks have O(1) push and pop.

Stack Overflow vs. Stack Underflow

Stack overflow occurs when you try to push onto a full stack (for fixed-size implementations). In Python, it means excessive recursion depth. Stack underflow occurs when you try to pop from an empty stack. Good implementations check for this (the code above raises IndexError on pop if empty).

Prefix, Infix & Postfix Notation
High exam weight. Conversion between formats and stack-based evaluation were directly tested.

The Three Formats

These are different ways to write arithmetic expressions. The difference is where you place the operator relative to its operands.

Infix (normal writing)

  • Operator is BETWEEN operands
  • Example: A + B
  • Needs parentheses for precedence
  • What humans naturally write

Prefix (Polish)

  • Operator is BEFORE operands
  • Example: + A B
  • No parentheses needed
  • Read operator, then operands

Postfix (Reverse Polish) ← Most important for exams

  • Operator is AFTER operands
  • Example: A B +
  • No parentheses needed
  • Ideal for stack-based evaluation (used by compilers)
Infix Prefix Postfix
A + B + A B A B +
A + B * C + A * B C A B C * +
(A + B) * C * + A B C A B + C *
A + (B - C) + A - B C A B C - +

Converting Infix → Postfix (Shunting-Yard Algorithm)

Use a stack for operators. Precedence: * / higher than + -. Parentheses force grouping.

1

Read left to right

Operands (A,B,C numbers) → output immediately. Operators → push to stack (pop higher/equal precedence first). Left paren → push. Right paren → pop until left paren.

2

End of expression

Pop all remaining operators from stack to output.

Python — Infix to Postfix
def infix_to_postfix(expression):
    precedence = {'+':1, '-':1, '*':2, '/':2}
    stack = []
    output = []

    for token in expression.split():
        if token.isalnum():            # Operand → output
            output.append(token)
        elif token == '(':
            stack.append(token)
        elif token == ')':
            while stack and stack[-1] != '(':
                output.append(stack.pop())
            stack.pop()                # Remove '('
        else:                          # Operator
            while (stack and stack[-1] != '(' and
                   precedence.get(stack[-1],0) >= precedence[token]):
                output.append(stack.pop())
            stack.append(token)

    while stack:
        output.append(stack.pop())

    return ' '.join(output)

# Test:
print(infix_to_postfix("A + B * C"))    # → A B C * +
print(infix_to_postfix("( A + B ) * C")) # → A B + C *
EXAM WORKED EXAMPLE: Convert (a + (b − c)) * ((d − e) / (f + g − h)) to prefix. Answer: * +a −bc /−de −+fgh. The key is working from innermost parentheses outward.

Evaluating Postfix with a Stack

1

Scan left to right

If operand → push to stack. If operator → pop two operands, apply operator, push result.

2

Final result

At the end, the stack contains exactly one value — the answer.

Python — Evaluate Postfix Expression
def evaluate_postfix(expression):
    stack = []
    for token in expression.split():
        if token.lstrip('-').isdigit():  # Number
            stack.append(int(token))
        else:                             # Operator
            b = stack.pop()  # Second operand (popped first)
            a = stack.pop()  # First operand
            if   token == '+': stack.append(a + b)
            elif token == '-': stack.append(a - b)
            elif token == '*': stack.append(a * b)
            elif token == '/': stack.append(a / b)
    return stack[0]

print(evaluate_postfix("3 4 + 2 *"))  # → 14  (= (3+4)*2)

Operator Precedence & Associativity

When converting between notation forms, operator precedence determines the order of operations. Higher precedence operators bind more tightly. Associativity determines evaluation order when two operators have equal precedence (both usually left-to-right).

Operator Precedence Associativity
^ (exponent) Highest (3) Right-to-left
* / % Medium (2) Left-to-right
+ - Lowest (1) Left-to-right
( ) Overrides all precedence

Step-by-Step Shunting-Yard Trace: Convert "A + B * C - D"

Input: A + B * C - D Stack: [] Output: [] Token A → operand → output: [A] Token + → operator → stack: [+] Token B → operand → output: [A, B] Token * → higher precedence than + → stack: [+, *] Token C → operand → output: [A, B, C] Token - → lower/equal precedence than * → pop * Output: [A, B, C, *] - equal precedence to + → pop + Output: [A, B, C, *, +] Push - → stack: [-] Token D → operand → output: [A, B, C, *, +, D] End: pop remaining → output: [A, B, C, *, +, D, -] RESULT: A B C * + D - (Postfix)
PATTERN: When you see a closing parenthesis, pop operators until you hit the matching open parenthesis. When you see an operator with lower/equal precedence than the top of stack, pop the stack first before pushing the new operator.

Why Postfix (RPN) is Used by Computers

Postfix notation (Reverse Polish Notation, invented by Jan Łukasiewicz) is used by most language interpreters and stack-based calculators (like HP calculators, and the Java Virtual Machine's bytecode). The reason: postfix needs no parentheses and no precedence rules to evaluate — you just scan left to right, push operands, pop and apply operators. This makes evaluation fast and simple to implement.

Expression Trees — Another Way to Understand Notation

Any arithmetic expression can be represented as a binary expression tree where: leaf nodes are operands (A, B, C), and internal nodes are operators (+, *, -). The three traversals give you the three notations: In-order (left→root→right) = Infix; Pre-order (root→left→right) = Prefix; Post-order (left→right→root) = Postfix. This is why expression notation connects so tightly to tree traversals!

Queue — FIFO (First In, First Out)

A queue is like a real-world queue/line — first person in, first person out. Elements are added at the rear (enqueue) and removed from the front (dequeue). All operations are O(1).

EXAM: Queue = FIFO. All queue operations are O(1). Used for: scheduling, buffering, BFS traversal.
Python — Queue Implementation
from collections import deque

class Queue:
    def __init__(self):
        self.items = deque()

    def enqueue(self, item):  # O(1) - add to rear
        self.items.append(item)

    def dequeue(self):         # O(1) - remove from front
        if self.is_empty():
            raise IndexError("Queue empty")
        return self.items.popleft()

    def front(self):            # O(1) - peek at front
        return self.items[0] if self.items else None

    def is_empty(self): return len(self.items) == 0
    def size(self): return len(self.items)

Queue Variants

  • Circular Queue: The rear wraps around to the front when it reaches the end of the array — efficiently reuses space.
  • Priority Queue: Elements are dequeued based on priority, not just insertion order. Implemented with a heap.
  • Deque (Double-ended Queue): Can insert/remove from both front and rear.

Hash Tables

A hash table stores key-value pairs and uses a hash function to convert a key into an index. This gives O(1) average-case lookups — faster than any sorted structure.

EXAM: Best collision technique = Quadratic Probing (per your lecturer). Separate chaining is also valid in practice but your test showed Quadratic Probing as the answer.

Strategy How it works Type
Separate Chaining Each slot holds a linked list of elements that hash there Open hashing

class HashTable:
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(size)]

    def hash_function(self, key):
        return hash(key) % self.size   # Key → index

    def insert(self, key, value):    # O(1) average
        idx = self.hash_function(key)
        self.table[idx].append((key, value))

    def search(self, key):           # O(1) average
        idx = self.hash_function(key)
        for k, v in self.table[idx]:
            if k == key: return v
        return None

Hash Tables — Load Factor & Collision Resolution

The load factor (λ) measures how full the hash table is: λ = n / m where n = stored items, m = table size. When λ exceeds ~0.75, performance degrades. The solution is rehashing: create a larger table (usually 2×) and re-insert all elements.

Method Strategy Probe Sequence Problem
Linear Probing Open Addressing (h+i) % m Primary clustering
Quadratic Probing Open Addressing (h+i²) % m Secondary clustering
Double Hashing Open Addressing (h+i·h₂) % m Minimal clustering
Chaining Closed Addressing Linked list per bucket No clustering; extra memory

Quadratic Probing Worked Example

Insert 15: h(15)=1 → slot 1 empty → place at 1 Insert 22: h(22)=1 → conflict! probe (1+1²)%7=2 → place at 2 Insert 29: h(29)=1 → conflict at 1, probe 2 → conflict! probe (1+2²)%7=5 → slot 5 empty → place at 5 Table: [_][15][22][_][_][29][_] 0 1 2 3 4 5 6
EXAM TIP: The choice between chaining and open addressing affects load factor tolerance: chaining can exceed λ=1 (more items than slots), open addressing cannot. Quadratic probing does NOT visit all slots unless table size is a prime number.

Good Hash Function Properties

A good hash function must be: (1) Deterministic — same key always maps to same slot; (2) Uniform — keys should be distributed evenly to minimize collisions; (3) Fast to compute — O(1); (4) Minimal collisions — keys should rarely map to the same slot. A common technique is the division method: h(k) = k mod m, where m is a prime number (primes minimize collisions). Python uses a more sophisticated hash involving bit manipulation and randomization.

Why Python Dicts Use Hash Tables

Python's dict is implemented as an open-addressing hash table with a load factor threshold of ~0.67. When a dict reaches 67% full, Python automatically resizes it to 2× the capacity and rehashes all entries. This keeps lookup at amortized O(1). Python 3.7+ guarantees that dict maintains insertion order as a side effect of the implementation, not an ADT guarantee.

Circular (Ring) Queue — A Better Array-Based Queue

A naive array-based queue wastes memory: as you dequeue from the front, those slots can never be reused. A circular queue fixes this by treating the array as a ring: the front pointer wraps around to index 0 after reaching the end. Enqueue: rear = (rear + 1) % size. Dequeue: front = (front + 1) % size. A circular queue of capacity n can hold n-1 elements (one slot kept empty to distinguish full from empty).

Binary Search Tree (BST)

A BST is a binary tree with a critical property: for every node, all values in the left subtree are smaller, and all values in the right subtree are larger. This makes search O(log n) on a balanced BST.

8 / \ 3 10 / \ \ 1 6 14 / \ / 4 7 13 BST Property: left < node < right Search for 6: 8→right? No→left→3→right→6 ✓
EXAM: If a BST is not balanced, it may be less efficient than a linear structure (degenerates to O(n) for search). An AVL tree is a self-balancing BST.
Python — BST Implementation
class BSTNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

class BST:
    def __init__(self): self.root = None

    def insert(self, val):           # O(log n) balanced
        self.root = self._insert(self.root, val)

    def _insert(self, node, val):
        if not node: return BSTNode(val)
        if val < node.val:
            node.left = self._insert(node.left, val)
        elif val > node.val:
            node.right = self._insert(node.right, val)
        return node

    def search(self, val):           # O(log n) balanced
        return self._search(self.root, val)

    def _search(self, node, val):
        if not node: return False
        if val == node.val: return True
        if val < node.val: return self._search(node.left, val)
        return self._search(node.right, val)

        result.append(node.val)        # Node LAST

def level_order(root):             # BFS using queue
    from collections import deque
    result, queue = [], deque([root])
    while queue:
        node = queue.popleft()
        result.append(node.val)
        if node.left: queue.append(node.left)
        if node.right: queue.append(node.right)
    return result

🔴 BFS — Breadth First Search

Visit all neighbours at current depth before going deeper. Uses a queue. Finds the shortest path (by number of edges) in unweighted graphs.

Graph: A─B─D | | C───┘ BFS from A: Visit A → all A's neighbors (B, C) → all B's unvisited (D) Order: A, B, C, D
Python — BFS
from collections import deque

def bfs(self, start):
    visited = {start}
    queue = deque([start])
    order = []

    while queue:
        vertex = queue.popleft()    # Dequeue from front
        order.append(vertex)
        for neighbor in self.graph.get(vertex, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)  # Enqueue
    return order

# Complexity: O(V + E)

🔴 Dijkstra's Algorithm — Shortest Path

Finds the shortest path from one source vertex to ALL other vertices. It is a greedy algorithm. Works only with non-negative edge weights.

EXAM FACTS: Dijkstra = Single source shortest path. Dijkstra = Greedy algorithm. Dijkstra does NOT work with negative weights. Bellman-Ford handles negative weights.
1

Initialize

Set distance to source = 0, all others = ∞. Mark all vertices as unvisited. Create a priority queue.

2

Pick minimum

Select the unvisited vertex with smallest known distance. Mark it as visited.

3

Relax edges

For each unvisited neighbor: if (current dist + edge weight) < known dist, update the distance.

4

Repeat

Repeat steps 2-3 until all vertices are visited.

Worked Example (from your test — S as source): 2 A──────C │\ 1/│ 1 │ \ / │1 │ X │ 5 │ / \ │ │/ \ │ B──────D 2 \2→E→4 Init: S=0, A=∞, B=∞, C=∞, D=∞, E=∞ Pick S(0): Update A=1 (via S→A=1), B=5 (via S→B=5) Pick A(1): Update B=3 (1+2), C=3 (1+2), D=2 (1+1) Pick D(2): Update E=4 (2+2) Pick B(3): B→D = 3+2=5 > 2 → no update Pick C(3): C→E = 3+1=4 = 4 → no update Final: A=1, B=3, C=3, D=2, E=4
Python — Dijkstra's Algorithm
import heapq

def dijkstra(graph, source):
    # graph = {vertex: [(neighbor, weight), ...]}
    dist = {v: float('inf') for v in graph}
    dist[source] = 0
    pq = [(0, source)]  # (distance, vertex)

    while pq:
        curr_dist, u = heapq.heappop(pq)
        if curr_dist > dist[u]: continue  # Skip outdated

        for v, weight in graph[u]:
            new_dist = dist[u] + weight
            if new_dist < dist[v]:       # Relax edge
                dist[v] = new_dist
                heapq.heappush(pq, (new_dist, v))

    return dist

🔴 Kruskal's Algorithm — Minimum Spanning Tree

Finds the MST — a subset of edges connecting all vertices with minimum total weight. Kruskal is a greedy algorithm that works by sorting edges.

EXAM FACTS: Kruskal sorts edges in ASCENDING order. Prim is better for dense graphs (not Kruskal). Kruskal CAN work on disconnected graphs.
1

Sort all edges by weight (ascending)

List every edge from lightest to heaviest.

2

Pick edges greedily

Take the cheapest edge. Add it to the MST — but ONLY IF it doesn't form a cycle. Use Union-Find to detect cycles.

3

Stop when n-1 edges selected

For a graph with n vertices, the MST has exactly n-1 edges.

Graph from test (Kruskal MST example): Vertices: S, A, B, C, D, E Edges sorted: SA=1, AD=1, CE=1, AC=2, AB=2, BD=2, DE=2, CD=3, SB=5 Step 1: Add SA=1 ✓ (no cycle) Step 2: Add AD=1 ✓ (no cycle) Step 3: Add CE=1 ✓ (no cycle) Step 4: Add AC=2 ✓ (no cycle) Step 5: Add AB=2 ✓ (no cycle) → 5 edges for 6 vertices = n-1 ✓ MST weight = 1+1+1+2+2 = 7
Python — Kruskal's Algorithm
def kruskal(vertices, edges):
    # edges = [(weight, u, v), ...]
    edges.sort()              # Sort by weight ASCENDING
    parent = {v: v for v in vertices}

    def find(x):              # Find root (Union-Find)
        if parent[x] != x:
            parent[x] = find(parent[x])
        return parent[x]

    def union(x, y):
        parent[find(x)] = find(y)

    mst, total_weight = [], 0
    for weight, u, v in edges:
        if find(u) != find(v):  # No cycle!
            union(u, v)
            mst.append((u, v, weight))
            total_weight += weight
    print(f"MST edges: {mst}")
    print(f"Total weight: {total_weight}")
    return mst

🔴 Prim's Algorithm — Minimum Spanning Tree

Another MST algorithm. Starts from one vertex and greedily grows the MST by always adding the cheapest edge connecting the current MST to a new vertex.

Kruskal vs Prim: Kruskal works on disconnected graphs; Prim does NOT. Prim is better for dense graphs. Kruskal is better for sparse graphs. Both are greedy algorithms. Both produce MSTs.
Python — Prim's Algorithm
import heapq

def prim(graph, start):
    # graph = {vertex: [(neighbor, weight), ...]}
    visited = {start}
    edges = [(0, start, start)]  # (weight, from, to)
    mst, total = [], 0

    while edges:
        weight, u, v = heapq.heappop(edges)
        if v in visited: continue
        visited.add(v)
        mst.append((u, v, weight))
        total += weight
        for neighbor, w in graph.get(v, []):
            if neighbor not in visited:
                heapq.heappush(edges, (w, v, neighbor))

    print(f"MST: {mst}, Total weight: {total}")
    return mst

def linear_search(arr, target):

            return i     # Return index

Binary Search

Requires sorted array. Repeatedly halves the search space. O(log n) — dramatically faster than linear search for large datasets.

EXAM: Necessary condition for binary search = the array must be sorted (not necessarily ascending — just sorted).
1

Set low=0, high=n-1

Calculate mid = (low+high) // 2

2

Compare arr[mid] to target

If equal → found! If target > arr[mid] → search right half (low=mid+1). If target < arr[mid] → search left half (high=mid-1).

3

Repeat until found or low > high

If low > high → not found.

Python — Binary Search
def binary_search(arr, target):
    low, high = 0, len(arr) - 1

    while low <= high:
        mid = (low + high) // 2
        if   arr[mid] == target: return mid        # Found!
        elif arr[mid] <  target: low = mid + 1     # Go right
        else:                   high = mid - 1     # Go left
    return -1  # Not found

# Example: search for 7 in [1,3,5,7,9,11,13]
arr = [1,3,5,7,9,11,13]

Why Binary Search is Not Always Best

Binary search's O(log n) beats linear search's O(n) — but at a cost: the data must be sorted first. Sorting costs O(n log n). If you only need to search once, linear search is cheaper. Binary search wins when: the data is already sorted, or you'll search many times on the same dataset. If searches vastly outnumber insertions, maintain a sorted array and use binary search. If insertions and searches are balanced, a BST or hash table might be better.

Binary Search — Iterative vs Recursive

Binary search can be implemented iteratively (as shown in Section 2) or recursively. Both are O(log n) time. However, the recursive version uses O(log n) space for the call stack, while the iterative version uses O(1) space. In memory-constrained systems, always prefer the iterative version. Both are acceptable answers in an exam unless space complexity is specified.

Sentinel Search — Optimizing Linear Search

A minor optimization: place the target value at the end of the array (as a "sentinel"). Then your loop doesn't need to check the boundary condition (i < n) every iteration, only checking arr[i] == target. This halves the comparisons per step. Still O(n) worst case, but ~2x faster in practice due to fewer operations in the loop.

Bubble Sort

Repeatedly compare adjacent elements and swap if in wrong order. Larger elements "bubble up" to the end.

Python — Bubble Sort
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        swapped = False
        for j in range(0, n-i-1):  # Last i elements sorted
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
                swapped = True
        if not swapped: break  # Already sorted: O(n) best case
    return arr

Merge Sort — Divide & Conquer

Divide array in half, recursively sort both halves, then merge them back together. Guaranteed O(n log n).

Python — Merge Sort
def merge_sort(arr):
    if len(arr) <= 1: return arr   # Base case

    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])  # Sort left half
    right = merge_sort(arr[mid:])  # Sort right half

    return merge(left, right)

def merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    return result + left[i:] + right[j:]

Quick Sort — Divide & Conquer

Choose a pivot, partition: all smaller elements left, larger right. Recursively sort the partitions.

EXAM (QuickSort pivot question from test): After first partition, array looks like: 3 0 2 5 1 7 9 12 11 100 10. The pivot could be either 7 OR 9 (since both could be in their final sorted position). Correct answer: "The pivot could be either the 7 or the 9."
Python — Quick Sort
def quick_sort(arr, low=0, high=None):
    if high is None: high = len(arr) - 1
    if low < high:
        pi = partition(arr, low, high)
        quick_sort(arr, low, pi - 1)   # Sort left
        quick_sort(arr, pi + 1, high)  # Sort right

def partition(arr, low, high):
    pivot = arr[high]  # Last element as pivot
    i = low - 1
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i+1], arr[high] = arr[high], arr[i+1]
    return i + 1  # Pivot is now in final position

Algorithm Design Strategies
Greedy, Divide & Conquer, Dynamic Programming — the knapsack problems were heavily tested.
↑ High exam weight — especially knapsack problems

The Four Main Strategies

Strategy Key Idea Examples
Greedy Make locally optimal choice at each step. Never look back. Dijkstra, Prim, Kruskal, Fractional Knapsack
Divide & Conquer Divide into subproblems, solve recursively, combine results. Merge Sort, Quick Sort, Binary Search
Dynamic Programming Store solutions to overlapping subproblems to avoid recomputation. 0/1 Knapsack, Fibonacci, Longest Common Subsequence
Backtracking Build solution step by step, abandon (backtrack) if it leads to failure. N-Queens, Maze solving, Sudoku
Branch & Bound Like backtracking but uses bounds to prune branches early. Travelling Salesman, 0/1 Knapsack (alternate)
EXAM: Dijkstra = Greedy. Fractional Knapsack = Greedy. 0/1 Knapsack = Dynamic Programming (NOT greedy — this was confirmed in your test). Merge Sort, Quick Sort = Divide & Conquer.

🔴 Greedy Strategy

A greedy algorithm always makes the choice that looks best at the moment, hoping this leads to a globally optimal solution. It's fast but doesn't always give the optimal answer (except for specific problems like fractional knapsack, MST).

IMPORTANT: Greedy works for Fractional Knapsack but NOT 0/1 Knapsack. The difference: in fractional, you can take a fraction of an item (so always take best value/weight ratio first). In 0/1, you either take the whole item or leave it.

🔴 Knapsack Problems — Worked Examples

Fractional Knapsack (Greedy)

Sort items by value/weight ratio (descending). Take as much of the best ratio item as fits, then next best, etc.

From test: items = {(40,20),(30,10),(20,5)}, capacity = 20 Value/weight ratios: 40/20=2, 30/10=3, 20/5=4 Sort by ratio descending: (20,5,ratio=4), (30,10,ratio=3), (40,20,ratio=2) Take (20,5): value=20, remaining capacity=15 Take (30,10): value=30, remaining capacity=5 Take 5/20 of (40,20): value=40*(5/20)=10 Total value = 20+30+10 = 60 ← Correct answer from test
Python — Fractional Knapsack
def fractional_knapsack(items, capacity):
    # items = [(value, weight), ...]
    # Sort by value/weight ratio (highest first)
    items.sort(key=lambda x: x[0]/x[1], reverse=True)

    total_value = 0
    for value, weight in items:
        if capacity >= weight:
            total_value += value      # Take whole item
            capacity -= weight
        else:
            # Take fraction of item
            fraction = capacity / weight
            total_value += value * fraction
            break              # Knapsack full
    return total_value

# Test example:
items = [(40,20), (30,10), (20,5)]
print(fractional_knapsack(items, 20))  # → 60

0/1 Knapsack (Dynamic Programming)

Cannot take fractions. Use a 2D DP table where dp[i][w] = max value using first i items with capacity w.

From test: capacity=60, weights={20,30,40,70}, values={70,80,90,200} We can take items 20+30+? → 20+30=50, add 40 → 90 > 60 too heavy Best: weight=20(v=70) + weight=40(v=90) = 60, value=160 ← Correct answer
Python — 0/1 Knapsack DP
def knapsack_01(weights, values, capacity):
    n = len(weights)
    # dp[i][w] = max value with i items and capacity w
    dp = [[0]*(capacity+1) for _ in range(n+1)]

    for i in range(1, n+1):
        for w in range(1, capacity+1):
            # Option 1: Don't take item i
            dp[i][w] = dp[i-1][w]
            # Option 2: Take item i (if it fits)
            if weights[i-1] <= w:
                take = values[i-1] + dp[i-1][w-weights[i-1]]
                dp[i][w] = max(dp[i][w], take)

    return dp[n][capacity]

# Test from exam:
weights = [20, 30, 40, 70]
values  = [70, 80, 90, 200]
print(knapsack_01(weights, values, 60))  # → 160

Dynamic Programming — Fibonacci Example

Python — Fibonacci with DP (Memoization)
# Without DP: O(2^n) — exponential
def fib_naive(n):
    if n <= 1: return n
    return fib_naive(n-1) + fib_naive(n-2)

# With DP memoization: O(n) — linear
def fib_dp(n, memo={}):
    if n in memo: return memo[n]   # Already computed!
    if n <= 1: return n
    memo[n] = fib_dp(n-1,memo) + fib_dp(n-2,memo)
    return memo[n]

# With DP tabulation: O(n) time, O(n) space
def fib_tab(n):
    if n <= 1: return n
    dp = [0] * (n+1)
    dp[1] = 1
    for i in range(2, n+1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
